# M0 — Advisor — detect, predict, plan. No installer.

**Objective:** Prove we can tell a user what their machine can do, and be right, without touching their system.

**Duration:** 4–5 weeks · **Depends on:** none · **Unlocks:** M1, and the calibration flywheel

## 1. Scope

A detector, a signed catalog, a predictor, and a planner. The product of this milestone is a **plan** — a fully-resolved, ranked, explained proposal — and nothing else. No downloads, no installs, no services. The command is safe to run on any machine the user owns.

M0 is deliberately the highest-value, lowest-trust-cost artefact we can ship. It also forces the prediction to be correct *before* it becomes load-bearing.

## 2. Non-goals

- Installing, tuning, serving, or verifying anything.
- Windows-ARM install paths (detect only).
- Any plan for a platform outside Tier A/B.
- Telemetry.

## 4. Acceptance tests

Every item is a test that must exist and pass before the milestone closes. Format is Given/When/Then where the test is behavioural.

| ID | Given | When | Then |
|---|---|---|---|
| AT-0.1 | The M5 Pro reference host | `qinfer detect` runs | Reports `arch_id`, saturated bandwidth, single-thread bandwidth, and validates against `cfp@1` |
| AT-0.2 | The same host | `qinfer detect` is run with swap in use | Bandwidth is either accompanied by a low-confidence flag or refused — never published silently |
| AT-0.3 | A 3-model catalog | `qinfer plan qwen2.5-3b` | Returns ≥3 ranked plans, each with non-empty `rationale`, `risks`, and ≥2 `fallbacks` |
| AT-0.4 | A model too large for the machine | `qinfer plan <model>` | Exit code 3, with the fit arithmetic printed (weights + KV + headroom vs available) |
| AT-0.5 | The M5 Pro | Plans are generated for the 3 spike models | **Predicted rank order matches measured rank order** — the core promise |
| AT-0.6 | The spike models | Predictions are compared to `spikes/m0/results.json` | Decode MAPE ≤ 10 % against the already-measured ground truth |
| AT-0.7 | A machine with no network | `qinfer plan --offline` | Succeeds against a cached catalog; emits a staleness warning |
| AT-0.8 | An unsupported platform | `qinfer detect && qinfer plan` | Tier D response naming the reason and what would work |
| AT-0.9 | Any machine | `qinfer plan` is run | **No network I/O and no writes outside the state dir** (verified by tracing) |
| AT-0.10 | A cold start | `qinfer detect --fast` | Completes in < 2 s; full detect < 20 s |
| AT-0.11 | A fingerprint and results on disk | `qinfer` opens the dashboard | Renders machine, bandwidth and per-model rows; `q` exits; no listener is opened |
| AT-0.12 | The same data | `qinfer --snapshot 64x20` and `… 140x40` | Both render without panic or clipped values; narrow layout stacks |

**Property tests:** for any catalog entry, `plan` never proposes an artifact whose arch coverage excludes the fingerprint's `arch_id`.

## 5. Exit criteria

- AT-0.1 … AT-0.12 green on macOS arm64.
- ≥50 plans generated by ≥10 distinct users/machines, with ≥10 receipts of predicted-vs-measured collected manually (since M0 cannot self-verify).
- The rank-order test (AT-0.5) passes on at least two additional machines.
- No open P0 defect in detection.

## 6. Risks specific to this milestone

| Risk | Mitigation |
|---|---|
| Prediction is impressive but useless without measurement | M0 ships with a manual "I ran it, here's the number" capture path so the calibration store starts filling before M1 |
| Catalog curation becomes a bottleneck | Cap at 20 models; refuse breadth |
| Detection traps differ on machines we don't own | Ship `qinfer detect --diagnose` that dumps raw probe output for bug reports |

## 7. Demo script

On a clean Mac: `qinfer detect` (10 s), `qinfer plan qwen3-8b`, `qinfer explain`. Show the `why` lines and the risk line. Then show the same command on a machine that cannot run it, and show the refusal. Total: 90 seconds, no installation.
